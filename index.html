1 · 把案子放進來（每個案子一次）

【我要講的】

  結果怎樣、哪裡沒解決）

1.3

從舊檔案反推

不動你的檔案

手上有做過的提案、簡報、結案報告 —— 先讓它盤點，不要急著整理。

我這裡有一些做過的案子的舊檔案（提案、簡報、結案報告、往來紀錄）：

✔ 你應該拿到　一張表，你就知道該從哪幾個案子開始

2 · 找出重複的模式（累積 3 個案例之後）

2.1

找同構

不動你的檔案

「長得一樣」不是同產業，是底層問題相同、做法可以照搬。

請掃描 01_案例 裡所有的案例卡，找出「需求形狀長得一樣」的組合。

「長得一樣」不是指同一個產業，是指：
客戶要解決的底層問題相同、或是我的做法可以照搬。

每一組請給我：
- 涉及哪幾個案例
- 它們共同的「需求形狀」是什麼（一句話）
- 我的做法有多少比例是一樣的
- 判定：【表面像】產業一樣但問題不同
        【真的同構】底層問題相同、做法可以照搬

只回報，不要建立任何檔案。

✔ 你應該拿到　「真的同構」那幾組才有價值。一組都沒有，代表案例還不夠多，先回去做 1.1

2.2

抽成模式卡

只會新增

把 B 類同構組寫成模式卡。少於 2 個案例支撐的不准建。

根據剛才找到的「真的同構」那幾組，幫我建「模式卡」，存到 02_模式。

一個模式一張卡，內容包含：
- 這個模式解決的需求形狀（一句話）
- 出現在哪幾個案例（用 [[案例卡名]] 連結）
- 標準做法：分成幾步，每一步在做什麼
- 每一步需要什麼資源
- 哪幾步每次都一樣（可標準化）
- 哪幾步每次都不同 ← 這是產品化的瓶頸
- 歷史工時範圍：最少 __ 人日，最多 __ 人日

規則：
1. 只用案例卡裡真的有的內容，不足的標【待補】。
2. 少於 2 個案例支撐的，不要建卡——列出來告訴我就好。

【動手之前】先列出你打算建哪幾張，我說 OK 你才建。

✔ 你應該拿到　每張模式卡都連得回 2 個以上的案例

2.3

資源盤點

只會新增

你能調動誰、哪裡是單點風險。

請掃描所有案例卡的「我動用了什麼」，整理出資源卡，存到 04_資源。

一個資源一張卡（人用代號，不要真名），內容包含：
- 類型：人 / 工具 / 資料源 / 夥伴
- 他提供什麼能力
- 用在哪幾個案例（[[連結]]）
- 調動難度：隨時可以 / 要排期 / 看關係 / 不確定還在不在
- 有沒有替代方案

最後另外告訴我：
★ 哪些資源被 2 個以上的案例依賴，但【只有一個來源】？
   —— 這是我的單點風險。

✔ 你應該拿到　一份資源名冊 ＋ 一張單點風險清單

2.4

交付物盤點

只會新增

哪一份被重用最多次 —— 那就是可以商品化的模板。

請掃描所有案例卡的「產出了什麼」，整理出交付物卡，存到 05_交付物。

每一張包含：
- 這是什麼（報告 / 模型 / 工作坊 / 檢查表 / 簡報…）
- 原本為哪個案例做的（[[連結]]）
- 被重用過幾次、用在哪些案例
- 重用時要改多少：幾乎不用改 / 改一半 / 等於重做
- 現在檔案放在哪

最後告訴我：★ 哪一份被重用最多次？改動最少？
—— 那一份最有機會直接商品化。

✔ 你應該拿到　重用次數排行

【動手之前】先貼給我看，我說 OK 你才存。

✔ 你應該拿到　一張有價格區間、有證據案例、有版本記錄的產品卡

3.2

產品化瓶頸

不動你的檔案

最靠你個人判斷的那一步，就是這個產品現在賣不動的原因。

請看 03_產品 裡的【產品名稱】，回答我三件事：

1. 交付步驟裡，哪幾步是「換一個人做也會一樣」的？
2. 哪幾步是「只有我做得來」的？為什麼——是因為經驗、關係、
   還是因為那一步根本還沒想清楚？
3. 如果我要讓別人也能交付這個產品，最先要把哪一步文件化？

規則：每個判斷都要指出是根據哪幾個案例卡的哪一段。
只回報，不要修改任何檔案。

✔ 你應該拿到　你會知道這個產品現在是「可以複製」還是「只能你自己做」

4 · 交付完回流（每次結案）

4.1

結案回流

只會新增

閉環就靠這一步。不做這一步，產品不會進化。

我剛結束一個案子，用的是產品【產品名稱 v?】。

請先幫我建這個案子的案例卡（照 1.1 的流程），
然後回答一個問題：

★ 這次有沒有東西該進產品？

只有三個答案，請幫我判斷並說明理由：
  □ 不用——這次跟前幾次一樣
  □ 改流程——哪一步、為什麼（引用這次案例卡裡的哪一句）
  □ 多一份可重用的交付物——哪一份、可以用在什麼情況

如果是後兩者，請草擬產品卡的新版本，
在「版本記錄」加一行，寫明【憑哪個案例改的】。

【動手之前】不要改產品卡，先把建議給我看。

✔ 你應該拿到　一張新案例卡 ＋ 一個明確的「改 / 不改」判斷

4.2

產品改版

會覆蓋

每一次改版都要指得回是哪幾個案例逼你改的。

請把【產品名稱】從 v_ 更新到 v_。

改動內容：
【寫你要改什麼】

規則：
1. 在「版本記錄」加一行：版本 / 改了什麼 / 憑哪幾個案例 / 日期。
   「憑哪幾個案例」必須是真的存在的案例卡，用 [[連結]]。
2. 舊版本的內容不要刪除——搬到卡片最下面的「歷史版本」區保留。
3. 只改我指定的部分，其他一個字都不要動。

【動手之前】先用表格給我看：
| 段落 | 原本寫什麼 | 改成什麼 | 憑哪個案例 |
我逐條說 OK 之後你才寫進檔案。

✔ 你應該拿到　改完之後你三個月後還看得懂當初為什麼改

5 · 拿出去變現

5.1

去識別化 case study

只會新增

給 prospect 看的一頁。估的數字一律不准寫進去。

請把 [[案例卡名]] 改寫成一份可以給潛在客戶看的一頁 case study。

規則：
1.【去識別化】客戶名稱、人名、可辨識細節全部拿掉或模糊化
  （例如「一家 200-500 人的精密製造商」）。
2. 只用「結果」欄裡標明是「客戶說的」或「我量的」的數字。
  【標成「我估的」一律不要寫進去】。
3. 結構：客戶原本的處境 → 真正的問題 → 我們做了什麼 → 結果 → 適合誰
4. 不要加任何案例卡裡沒有的形容詞。

寫完告訴我：哪些內容我應該再確認一次能不能對外講。

✔ 你應該拿到　一份可以直接寄出去的一頁，而且每個數字你都敢認

5.2

新需求 → 提案骨架

不動你的檔案

線索進來，十分鐘給得出可信回答。

有一個新的需求進來：
【描述這個需求，客戶原話最好】

請根據我的知識庫回答：
1. 我做過最像的三個案例是哪幾個？像在哪裡、不像在哪裡？
2. 有沒有現成的模式或產品可以直接套？
3. 如果要接，大概要幾人日？（用歷史案例的工時範圍）
4. 需要調動哪些資源？有沒有我現在調不動的？
5. 根據以上，草擬一份提案骨架。

規則：
- 每一個判斷都要標明是根據哪一張卡。
- 知識庫裡沒有依據的，直接說「這部分我沒做過」，不要推測。

✔ 你應該拿到　三個同構案例 ＋ 工時區間 ＋ 一份骨架。而且每句話指得回卡

5.3

能力地圖

不動你的檔案

不是你自我介紹的說法，是從案例反推「你實際上會做什麼」。

根據我的知識庫，幫我做一份「我實際上會做什麼」的清單。

不要用我自我介紹的說法，要從案例反推：
1. 我實際交付過哪幾類東西？各做過幾次？
2. ★ 哪些做法我做過 3 次以上？（這些是可以標價的）
3. 哪些我只做過一次？（現在還不能當產品賣）
4. ★ 哪些「沒解決的部分」重複出現？（這是我的下一個服務）
5. 我的單點風險在哪——哪些資源只有一個來源？

用表格，每一列標明依據哪幾張卡。

✔ 你應該拿到　你會看到自己真正的產品線，而不是你以為的那一條

5.4

它還能生出什麼

不動你的檔案

問一句，它自己列清單，還把指令寫好。

根據我這個知識庫，我可以做出什麼東西？
請分類列出，每一種都告訴我：產出格式、給誰用、
大概能做成什麼樣子，並且直接把可以執行的指令寫好，
讓我複製就能用。

✔ 你應該拿到　一份你沒想過的產出清單

6 · 維護

6.1

體檢

不動你的檔案

顧問版的體檢問的不是壞連結，是「哪個產品在腐爛」。

請幫我的知識庫做一次健康檢查，只回報不修改：

1. 有幾張案例卡的「結果」是空的或還標著【待補】？
2. 有哪些案例還沒有連到任何模式？
3. 有哪些模式支撐的案例少於 2 個？（不夠格當模式）
4. ★ 有哪些產品超過 6 個月沒有新的交付案例？（可能已經過時）
5. ★ 有哪些資源被 2 個以上產品依賴，但只有一個來源？
